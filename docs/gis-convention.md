# GIS Convention

## 좌표 원칙

- API와 저장소가 사용하는 기준 좌표계는 실제 데이터·API 명세에서 확인한다.
- 좌표는 항상 좌표계(SRID 또는 CRS), 축 순서, 단위를 함께 해석한다.
- 경도·위도와 투영 좌표를 이름이나 배열 모양만으로 추측하지 않는다.
- 좌표 변환은 변환 지점을 명확히 하고 중복 변환을 피한다.

## OpenLayers 표현

- 지도 View의 투영과 입력 Feature의 투영을 구분한다.
- GeoJSON 등 공간 데이터를 읽고 쓸 때 데이터 투영과 화면 투영을 명시한다.
- 원본 Geometry를 화면 표시 편의를 위해 조용히 변형하지 않는다.
- 레이어는 목적별로 분리하고 선택·강조·임시 편집 상태를 원본 데이터와 구분한다.
- 대량 Feature는 렌더링 비용과 요청 범위를 고려한다.

## 공간 의미와 단위

- 거리, 고도, 시간, 경사도는 API가 제공한 단위와 산정 기준을 보존한다.
- 지리 좌표를 단순 평면 좌표처럼 계산하지 않는다.
- 화면 표기를 위해 단위를 변환하면 원본 값과 변환 규칙을 구분한다.
- 범례, 툴팁, 차트 축에는 사용자가 해석할 수 있는 단위를 표시한다.

## 경로와 분석 결과

- 코스 선형은 서버가 반환한 순서와 방향을 유지한다.
- 출발·도착점, 경유점, 네트워크 스냅 결과를 서로 다른 개념으로 취급한다.
- 경로 없음, 연결 불가, 분석 데이터 결측은 임의의 Geometry나 수치로 보완하지 않는다.
- ECharts의 고도 프로파일 등은 Backend 분석 결과의 표본 순서와 단위를 유지한다.

REST 전송 형식은 `api-convention.md`, GIS UI 구현은 `frontend-convention.md`, 경계값 검증은 `testing-convention.md`를 따른다.
