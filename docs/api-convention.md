# API Convention

## 범위

이 문서는 Frontend가 소비하는 Backend REST 계약의 표현 원칙을 정의한다. 실제 endpoint와 필드는 Backend의 API 명세를 기준으로 하며 여기서 추측하지 않는다. API 명세 문서 위치는 미확정이다.

## REST 계약

- 경로는 `/api`로 시작한다. 개발 서버에서는 Vite 프록시가 `/api`를 Backend로 전달한다.
- 리소스는 명사 중심의 일관된 경로로 표현한다.
- `GET`은 조회, `POST`는 생성 또는 명령, `PUT`은 전체 교체, `PATCH`는 부분 수정, `DELETE`는 삭제에 사용한다.
- 성공과 실패를 HTTP 상태 코드로 구분한다.
- 날짜·시간은 ISO 8601 문자열로 교환하고 시간대 의미를 유지한다.
- 열거값과 식별자는 문자열 표현과 대소문자를 계약에 명시한다.
- 목록의 페이지 방식, 정렬 키, 필터 문법은 endpoint별 계약에 명시한다.

## 요청과 응답

- API 요청 함수는 각 기능의 `api/`에 두고 endpoint와 전송 타입을 캡슐화한다.
- TypeScript 타입은 실제 계약을 반영하며 타입 단언으로 불일치를 숨기지 않는다.
- 선택 필드, `null`, 빈 배열은 계약에 정의된 의미대로 처리한다.
- 공간 데이터는 GeoJSON(EPSG:4326)으로 받는다. 세부 기준은 gis-convention를 따른다.

## 오류

현재 기준:

```json
{
  "status": 404,
  "code": "ROUTE_NOT_FOUND",
  "message": "해당 지점 사이에서 이동 가능한 경로를 찾지 못했습니다."
}
```

- `status`는 HTTP 상태 코드와 같은 값이다. 로그·디버깅 확인용으로 쓴다.
- 화면 분기는 `code` 기준으로 하고, `message`는 그대로 보여 줄 수 있는 문장으로 취급한다. 같은 404라도 `code`에 따라 안내가 다르다.
- `fieldErrors`(입력 필드별 오류)와 `traceId`는 Backend에서 추가 예정이다. 추가되면 타입을 갱신한다.
- 서버 내부 예외·SQL·스택 트레이스는 노출되지 않는다는 전제로 처리한다.

네트워크 실패, 요청 취소, 인증 실패, 권한 부족, 유효성 오류, 리소스 미존재, 서버 오류를 구분한다. 경로 탐색은 경로 없음과 스냅 실패를 다른 안내로 보여 준다. 재시도 정책은 요청의 멱등성과 사용자 경험을 고려해 frontend-convention에 따라 적용한다.

## 계약 변경

계약 변경은 FE와 BE가 함께 검토한다. 기존 소비자를 깨는 변경은 명시적으로 합의하며, 한쪽 Repository에서만 필드나 의미를 먼저 확정하지 않는다. 협업 절차는 git-convention를 따른다.
