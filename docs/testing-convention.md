# Testing Convention

## 원칙

테스트는 구현 세부보다 사용자가 관찰하는 동작과 모듈의 계약을 검증한다. 테스트 도구와 실행 명령은 Repository에 실제로 설정된 구성을 사용하며, 이 문서에서 특정 미확정 도구를 강제하지 않는다.

## 범위

- 유틸리티와 변환 로직: 입력, 출력, 경계값, 오류 조건
- React 컴포넌트: 렌더링, 사용자 상호작용, 접근 가능한 결과
- 기능 흐름: 로딩, 성공, 빈 결과, 오류, 재시도 상태
- API 계층: 요청 파라미터와 응답 매핑 계약
- GIS: CRS/축 순서, 좌표 변환, Geometry 없음·경계 조건
- 핵심 사용자 여정: 실제 라우팅과 주요 화면 간 연동

## 작성 규칙

- 테스트 이름은 조건과 기대 결과를 드러낸다.
- 외부 통신은 테스트 경계에서 통제하고 내부 구현을 과도하게 모킹하지 않는다.
- 시간, 난수, 화면 크기처럼 결과를 흔드는 요소는 명시적으로 제어한다.
- 단순 스냅샷만으로 중요한 동작을 대신하지 않는다.
- 버그 수정에는 가능한 경우 재현 테스트를 먼저 추가한다.

## 완료 기준

변경 파일의 정적 검사, 타입 검사, 관련 테스트, 빌드 중 Repository가 제공하는 항목을 실행한다. 실패하면 원인과 미해결 범위를 보고한다. 실행하지 못한 항목은 성공으로 표시하지 않는다.

테스트 대상의 책임은 `architecture.md`, API 경계는 `api-convention.md`, GIS 기준은 `gis-convention.md`를 따른다.
